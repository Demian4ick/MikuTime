# Статистика в Obsidian

## Подключение

1. Откройте **Настройки → Система → Хранилище для Обсидиана**.
2. Нажмите **Выбрать папку хранилища** и укажите существующую папку. Не выбирайте `.obsidian`.
3. Miku Focus будет обновлять статистику в `Miku Focus/Данные/linux.json` или `windows.json` внутри выбранной папки.

Заметки и настройки Obsidian приложение не трогает. Выгрузка работает и в обычную папку, без установленного Obsidian.

При работе с двумя ОС выберите общее хранилище в каждой из них. Путь может различаться: например, `D:\Заметки` в Windows и `/mnt/shared/Заметки` в Linux. История каждой ОС остаётся отдельной; таймеры не синхронизируются.

## Панель с графиками

Готовые заметки и Dataview-панель находятся в [`integrations/obsidian`](../integrations/obsidian/).

1. Установите Dataview в Obsidian и включите JavaScript-запросы.
2. Создайте в хранилище такую структуру:

   ```text
   Дневник/Статистика/
     FocusMikuArch/
       Статистика Arch.md
     FocusMikuWin/
       Статистика Windows.md
     FocusMikuAll/
       Статистика Miku Focus.md
       Как устроена статистика.md
       Панель/
         view.js
         view.css
   ```

3. Скопируйте файлы из репозитория в соответствующие папки.
4. В Linux выберите папку **FocusMikuArch** для выгрузки, в Windows — **FocusMikuWin**.
5. Откройте **Статистика Miku Focus** в режиме чтения.

Если используете другие папки, измените пути в заметках и настройках `view.js`. Панель показывает рабочее время, отдых, завершённые сессии, календарь и категории за выбранный период. При отсутствии одной выгрузки вторая продолжает работать.

## Обновление данных

Статистика записывается после действий таймера и примерно каждые 30 секунд во время работы. Можно обновить её вручную кнопкой в настройках.

Если внешний диск недоступен, локальная история продолжает сохраняться. Проверьте подключение диска и нажмите **Обновить выгрузку**. Отключение выгрузки не удаляет уже созданные файлы.

JSON содержит последний сохранённый снимок, а не живой таймер. Не редактируйте его вручную: следующая выгрузка заменит изменения. Для резервной копии приложения нужны локальные `state.json` и папка ресурсов, а не только эти JSON.

## Формат для своих отчётов

| Поле | Содержимое |
|---|---|
| `format`, `schemaVersion` | `miku-focus-statistics`, `1` |
| `source.id`, `source.os` | Идентификатор установки и ОС |
| `capturedAt`, `exportedAt` | Время снимка и записи файла |
| `categories` | ID, название, цвет, признаки архива и удаления |
| `sessions` | Рабочие сессии, включая текущую ровно один раз |
| `breaks` | Сегменты отдыха |
| `currentSessionId` | Ссылка на текущую сессию или `null` |
| `totals` | Рабочее время, отдых, завершённые сессии и продления |

Время и длительности указаны в миллисекундах. Работа считается по `segments`, не по промежутку между началом и концом сессии. Паузы и ожидание решения не входят в работу.

Для двух ОС суммируйте разные `source.id`. Ключ сессии — сочетание `source.id` и `session.id`. Категории разных установок не объединяются по имени автоматически. Повторную копию одной истории нельзя считать независимой работой.
