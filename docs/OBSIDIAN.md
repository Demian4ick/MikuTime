# Автовыгрузка статистики в Obsidian

## Подключение

В Miku Focus откройте **«Настройки» → «Система» → «Хранилище для Обсидиана» → «Выбрать папку хранилища»**. Выберите корень существующего хранилища, не каталог `.obsidian`. Можно выбрать и обычную существующую папку: Obsidian для выгрузки не нужен.

Приложение создаёт только собственные подкаталоги:

```text
<выбранная папка>/
  Miku Focus/
    Данные/
      linux.json
      linux.lock
      windows.json
      windows.lock
```

Каждая ОС создаёт и обновляет только свою пару файлов. `.lock` — маленький служебный файл блокировки, его не нужно читать в отчётах. Существующие заметки и настройки Obsidian не изменяются. Новые файлы с датами при каждом обновлении не создаются: JSON целиком заменяется актуальным снимком.

В Windows и Arch выберите **тот же общий том и хранилище**, но путь в каждой ОС задайте её собственный: например, `D:\Заметки` и `/mnt/shared/Заметки`. Сам путь и идентификатор источника хранятся локально в `obsidian.json` рядом с `state.json`, а не в Obsidian; предыдущая версия настроек сохраняется в `obsidian.backup.json`. Права записи и монтирование тома должны уже быть настроены пользователем; приложение не меняет настройки системы. Служебная папка `.obsidian` и её подкаталоги не принимаются как место выгрузки.

## Когда обновляется файл

- После подключения, запуска приложения, изменений истории/категорий/дневной цели и действий таймера.
- Во время работы и отдыха — на существующих контрольных точках примерно раз в 30 секунд.
- При выходе — финальный снимок; ожидание внешнего диска ограничено двумя секундами. Локальное сохранение по-прежнему обязательно.
- «Обновить выгрузку» принудительно обновляет файл вручную. Неизменившиеся данные при обычном сохранении не записываются повторно.

Работающий таймер в JSON — **снимок уже отработанных сегментов**, не живой таймер. Не прибавляйте к нему время с момента выгрузки: закрытое приложение, пауза и ожидание решения не являются работой.

Если диск пропал/стал недоступен, локальная история продолжает сохраняться. В настройках показана ошибка и время последнего успеха; повторная попытка — на существующих пробуждениях сервиса не чаще раза в 30 секунд либо кнопкой обновления. Отсутствующий корень/каталог выгрузки автоматически не создаётся заново: это защищает от записи в пустую точку монтирования. Если каталог намеренно удалён, выберите папку повторно.

Отключение отменяет дальнейшие записи, но **не удаляет** уже созданные файлы. Ручные изменения корректного JSON этого источника при следующей выгрузке будут заменены: собственные заметки храните отдельно. Повреждённый JSON, неизвестная версия/формат или файл другого экземпляра приложения не перезаписывается. В последнем случае сохраните старую выгрузку отдельно и освободите имя файла вручную, только если хотите заменить источник. Пути-ссылки внутри собственных подкаталогов и ссылки вместо файлов отвергаются.

## Формат JSON, версия 1

Это отдельный аналитический формат, **не копия `state.json` и не файл восстановления таймера**. В него не входят голоса, изображения, настройки звуков, положение окон, абсолютные пути ресурсов или путь самого хранилища.

| Поле | Смысл |
|---|---|
| `format` | Всегда `miku-focus-statistics` |
| `schemaVersion` | Версия аналитического формата, сейчас `1` |
| `appVersion` | Версия приложения, сформировавшего файл |
| `source.id` | Стабильный идентификатор этой установки/локальных данных |
| `source.os` | `linux` или `windows` |
| `exportedAt` | Время записи снимка, Unix milliseconds |
| `capturedAt` | Время фиксации статистики, Unix milliseconds |
| `categories` | Категории: `id`, `name`, `color`, `archived` |
| `sessions` | Вся история, включая текущую незавершённую сессию **ровно один раз** |
| `currentSessionId` | ID текущей сессии либо `null`; это ссылка на `sessions`, не дополнительная сессия |
| `breaks` | Все сегменты отдыха, включая фактическую часть текущего отдыха |
| `timerStatus`, `timerPhase` | Состояние на момент снимка; для информации, не для продолжения отсчёта |
| `dailyGoalMinutes` | Текущая дневная цель этой установки, не исторический журнал целей |
| `totals.workMs` | Сумма фактических рабочих сегментов всех сессий, в том числе частичных |
| `totals.breakMs` | Отдых отдельно от работы |
| `totals.completedSessions` | Количество завершённых сессий, без текущих/частичных |
| `totals.extensions` | Общее количество продлений |

Сессия содержит `id`, `categoryId`, `startedAt`, `endedAt`, `segments`, `extensions`, `completed`. Каждый сегмент работы/отдыха содержит `startMs`, `endMs`. Все timestamps и длительности — **миллисекунды**. Длительность сегмента: `max(0, endMs - startMs)`. Продления остаются в исходной сессии. Рабочие сегменты уже ограничены дедлайном; паузы и ожидание решения в них не входят.

## Объединение двух ОС

1. Читайте только актуальные `linux.json` и `windows.json`, не архивные копии, `.tmp` или `.lock`.
2. Проверьте `format` и `schemaVersion`. Для выбора ОС используйте `source.os`.
3. Для общего рабочего времени сложите `totals.workMs` двух **различных источников**. Для завершённых сессий — `totals.completedSessions`. Перевод в часы: `/ 3_600_000`.
4. Для деталей объедините массивы `sessions`, сохранив у каждой записи `source.id` и `source.os`. Ключ записи — **`source.id + session.id`**, а не только ID сессии. При загрузке нового снимка заменяйте предыдущие данные источника, не дописывайте их в конец.
5. Пользовательские категории разных установок могут иметь разные ID даже с одинаковыми именами. Их объединение задайте явно; одноимённые категории не обязательно означают одно и то же.
6. Для графиков по дням распределяйте **рабочие сегменты**, а не промежуток `startedAt…endedAt`. Выберите один часовой пояс для обоих источников и делите сегменты на местных полуночах, учитывая переходы часового пояса. Для средней длительности берите только завершённые сессии, как в Miku Focus.

Сами отчёты и графики в этой версии не создаются. Их можно построить плагином/скриптом Obsidian либо внешним инструментом, не меняя Miku Focus. Переноса истории обратно в приложение и синхронизации таймеров между ОС нет. Если вы вручную клонировали одну историю в две ОС, её копии нельзя суммировать как независимую работу.

Автовыгрузка не заменяет резервную копию локальных данных, особенно если хранилище находится на том же физическом диске.
