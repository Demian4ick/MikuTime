# Готовые сборки и GitHub Releases

## Бесплатно ли это

По [документации GitHub](https://docs.github.com/en/billing/concepts/product-billing/github-actions), проверенной **24 ноября 2026**:

- **Публичный репозиторий:** стандартные GitHub-hosted Linux/Windows runner бесплатны. Наш workflow использует только такие runner, не larger runner.
- **Закрытый репозиторий:** расходуется включённая месячная квота владельца. В текущей документации GitHub Free — **$12 эквивалента вычислений/месяц** и **500 МБ artifacts**; Windows и Linux имеют разные ставки. Это включённый лимит, не плата за подключение workflow. Точные остаток/тариф нужно смотреть в аккаунте: они не проверялись и не изменялись агентом.
- При наличии платёжного метода сверхлимит может оплачиваться. Чтобы не было неожиданных списаний, в **Settings аккаунта → Billing and licensing → Budgets and alerts** создайте бюджет для Actions **$0** с **Stop usage when budget limit is reached**. Без платёжного метода GitHub блокирует превышение квоты. Workflow не может надёжно прочитать/ограничить общий бюджет аккаунта самостоятельно.

### Защита именно для этого репозитория

По явному запросу владельца **24 ноября 2026 репозиторий стал PUBLIC**. Стандартные Windows/Linux runner теперь бесплатны. Защита для private сохранена на случай будущего закрытия: пока репозиторий закрытый, workflow **не выделяет runner автоматически**, если владелец не разрешил приватные сборки:

1. Разовый ручной запуск: отметьте **allow_private_build** — подтверждение расхода квоты только для данного запуска.
2. Для автосборок по тегам: после настройки бюджета добавьте repository variable **`ENABLE_PRIVATE_BUILDS=true`** в **Settings → Secrets and variables → Actions → Variables**.

Ни бюджет, ни переменная не устанавливаются этим кодом автоматически. Если репозиторий станет публичным, подтверждение не нужно. Менять видимость репозитория — отдельное решение владельца; код/установленные пользовательские ресурсы не должны случайно стать публичными.

## Что делает workflow

Файл: [`.github/workflows/release.yml`](../.github/workflows/release.yml).

**Не запускается** на обычный push ветки, PR, коммит документации, расписание или открытие Releases. Запускается только:

- после push тега `vX.Y.Z` или `vX.Y.Z-beta.N` — обе платформы, затем **черновик**, не опубликованный релиз;
- вручную через **Actions → Готовые сборки Miku Focus → Run workflow** — выбранная платформа/обе, **только artifacts**, без тега и релиза.

Сначала дешёвая проверка версий, Svelte/TypeScript и TS-тестов. Затем независимые сборки:

| Файл | Где собирается | Для кого |
|---|---|---|
| `Miku-Focus-X.Y.Z-windows-x64-setup.exe` | `windows-2022`, Rust MSVC, Tauri NSIS | Windows 10/11 x64 |
| `miku-focus-X.Y.Z-1-x86_64.pkg.tar.zst` | Официальный одноразовый `archlinux:base-devel` на Ubuntu runner | Актуальный Arch Linux x86_64 |

Arch-пакет собирается **в настоящем Arch-контейнере**, не из Ubuntu-бинарника. Установка зависимостей и `pacman -Syu` выполняются только внутри одноразового облачного контейнера. Никакие команды установки/обновления из workflow не исполняются на компьютере пользователя. Компиляция и makepkg идут от непривилегированного builder; `--nodeps` не используется. Rust jobs=1 и отключённые debug symbols сохраняются. Node/Rust/зависимости берутся только для runner; локальная система не меняется.

Windows использует [`tauri.windows.conf.json`](../src-tauri/tauri.windows.conf.json): установщик по-русски, для текущего пользователя, без обязательного admin. Сборка без подписи издателя: возможен SmartScreen. При отсутствии WebView2 установщик скачивает официальный Microsoft bootstrapper/runtime, нужен интернет; сама работа приложения остаётся локальной. Кодовая подпись и полностью офлайн-установщик WebView2 сейчас не настроены.

Используются `npm ci` и Cargo `--locked`; actions закреплены полными SHA. App-data, assets пользователя, архивы озвучки, история, `.local-test` и секреты не загружаются. В allowlist только два установщика, `SHA256SUMS.txt` и `BUILD_INFO.json` (версия, исходный SHA, хеши пакетов). Полный Rust/Node-кэш не сохраняется; временные artifacts живут **3 дня**, дублирующие запуски одного ref отменяются. Это уменьшает расход, но не заменяет бюджет аккаунта. Таймауты: 10 минут проверки, до 45 минут на каждую платформу, 10 минут сборки черновика.

Только финальный job имеет `contents: write`. Он работает лишь после успеха обеих платформ и создаёт/обновляет **draft**. Повторный запуск может заменить файлы только в черновике этого тега. Опубликованные релизы не изменяются. Ошибки API не принимаются за отсутствие релиза; сборка с неожиданными файлами не публикуется.

## Где скачать ручную проверочную сборку

**Actions → нужный запуск → Artifacts**: `miku-focus-windows-x64` или `miku-focus-arch-x64`. Скачайте ZIP и извлеките установщик/пакет. Для artifact нужна авторизация GitHub; он временный и не является ссылкой для обычных пользователей. Даже успешная сборка не доказывает визуальную корректность/работоспособность установщика.

Если доступ к Actions запрещён политикой репозитория/организации или квота исчерпана, GitHub покажет ошибку. Это не ошибка локального приложения. Для использования уже установленного приложения Actions не нужен.

## Выпуск версии

Workflow сам не создаёт тег и не публикует черновик. Нативная версия приложения пока **0.1.13**; текущая общедоступная бета готовится как **v0.1.13-beta.2**. Первый тег beta.1 не опубликован из-за ошибочного сравнения Windows-путей в тестах; тег не передвигался.

1. Согласуйте версию (например, `0.1.14`) во всех местах:
   - `package.json`;
   - `package-lock.json` — верхний `version` и `packages[""].version`;
   - `src-tauri/tauri.conf.json`;
   - `src-tauri/Cargo.toml`;
   - `src-tauri/Cargo.lock` — только запись пакета `miku-focus`;
   - `packaging/PKGBUILD` — `pkgver`.
2. Проверьте локально `node scripts/release.mjs check`, тесты и сборку. Не исправляйте lockfile сторонних библиотек вручную; используйте обычные npm/Cargo команды при смене версии.
3. Сделайте commit и push кода. **Обычный push не тратит Actions-квоту этого workflow.**
4. При необходимости сначала выполните ручную проверочную сборку (для private — с явным подтверждением).
5. Когда готовы запускать сборки версии:

   ```sh
   # Пример для будущей 0.1.14; версии в файлах уже должны совпадать.
   git tag v0.1.14
   git push origin v0.1.14
   ```

6. Дождитесь успеха двух сборок. В **Releases** появится **Draft: Miku Focus 0.1.14** с обоими пакетами, SHA-256 и исходным commit. При одной неуспешной платформе черновик не создаётся.
7. Скачайте и реально проверьте установку/запуск на Windows и Arch, обновление без потери данных, звук, tray/Waybar. Только компиляция Windows на GitHub — не ручная проверка Windows shell/DPI/звука. Проверьте права на изображения/звуки перед распространением.
8. Отредактируйте описание/список изменений в черновике и нажмите **Publish release**. Пример описания: [`.github/RELEASE_TEMPLATE.md`](../.github/RELEASE_TEMPLATE.md).

Не передвигайте опубликованный тег и не заменяйте готовые опубликованные пакеты — выпускайте следующую версию.

## Ссылка для обычного пользователя

**Бета: https://github.com/Demian4ick/MikuTime/releases/tag/v0.1.13-beta.2**

Бета публикуется с `prerelease: true`, не как latest stable. Семантический суффикс `-beta.N` относится к каналу публикации: core-версия в npm/Cargo/Tauri/PKGBUILD остаётся одинаковой, поэтому Arch pkgver не получает запрещённый дефис. `BUILD_INFO.json` содержит настоящий beta-тег и `channel: beta`. Пакеты носят core-версию; каталог GitHub-тега различает стабильный и beta-каналы.

Для будущих beta-тегов сохраняйте core-версию и меняйте номер beta, например `v0.1.13-beta.3`. Для новой core-версии сначала согласуйте все версии, как указано выше. По тегу создаётся только beta-draft; его публикует владелец через **Publish release** с **Set as a pre-release** либо через `gh release edit <тег> --draft=false --prerelease --latest=false` после проверки файлов. Уже опубликованные релизы workflow не меняет. Перед следующей бетой обновите ссылки/изменения в `.github/BETA_NOTES.md` и README под её тег.

`https://github.com/Demian4ick/MikuTime/releases/latest` предназначен для будущей стабильной версии. Беты и черновики туда не входят. Репозиторий теперь публичный, поэтому опубликованные beta-файлы доступны без приглашения/логина. Если владелец позже снова закроет его, публичное скачивание пропадёт. Автокопирования в другой репозиторий и отдельного PAT нет.

Обычному пользователю нужны `.exe` или `.pkg.tar.zst` из **Assets**, не **Source code**. AppImage/DEB/macOS/ARM этой схемой не обещаются.
