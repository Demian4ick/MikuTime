# Miku Focus — правила разработки

## Неизменяемые требования
- Desktop: Tauri 2, Svelte 5, TypeScript, Rust; Arch Linux/Hyprland Wayland и Windows 10.
- Всё локально. Не загружать сторонние изображения/озвучку Мику. Оригиналы `Sprites/` и `background.jpg` не менять.
- Один источник истины таймера — Rust; окна получают снимки и события. Паузы, ожидание решения и отдых не входят в работу. Продления не ограничены и принадлежат исходной сессии.
- Не менять Hyprland/system config, не удалять пользовательские файлы. sudo только с разрешения. Не выполнять `pacman -Syu` без отдельного разрешения.
- До установок проверять место на `/` и `/home`; кэши и сборки хранить в `/home`. Минимум зависимостей, без дублирования Rust/Node.
- Обновлять PROGRESS.md и PERFORMANCE.md. Проверять типы, тесты, сборку. Не выдавать Windows/визуальные проверки за выполненные без фактической проверки.

## Архитектура и решения
- JSON в app-data: настройки, категории, журнал сегментов и checkpoint таймера; атомарная запись и резервная копия. Невалидные файлы не затирать.
- После перезапуска работа восстанавливается на паузе на последнем checkpoint; отдых продолжается автоматически с оставшегося времени, без начисления времени закрытого приложения. Точность аварийного восстановления — до 30 секунд.
- Rust TimerService/SessionManager; TS StatisticsService, ReactionController, VoiceManager, EmotionManager; Rust SettingsStore, WindowManager, PlatformWindowAdapter, IdleDetectionAdapter.
- Hyprland: native Wayland + ext-idle-notify-v1; адресные runtime dispatchers только для собственных окон, без записи конфигурации. Ограничения compositor отображать, не скрывать.
- Hyprland 0.57+ использует Lua hl.dsp, старые версии — прежние dispatchers. Определять API одним read-only запросом, не менять конфиг; Lua resolve окна + проверка PID перед действием, legacy — проверка адреса/PID. Никогда не подставлять непроверенный адрес/пользовательский текст в Lua и не применять действия к activewindow по умолчанию.
- Нет анимационного цикла в фоне. Таймер работает по deadline, интерфейс обновляется раз в секунду только в видимых окнах. Аудио загружается по требованию.
- GTK app-id registration отключена: single-instance защищён файловой блокировкой, а не D-Bus reactivation (она вызывала повторный setup при тесте разных XDG_DATA_HOME). При заданном nvidia-drm GBM и отсутствующем nvidia-drm_gbm.so включать только в процессе приложения WebKit DMA-BUF compatibility workaround; глобальные настройки не трогать, пользовательский WEBKIT_DISABLE_DMABUF_RENDERER не переопределять.
- ID эмоций регистрозависимо сопоставляются именам: Neutral.png, Happy.png, Calm.png, pleased.png, Surprised.png, relief.png, Worried.png, dissatisfied.png, Angry.png, Sad.png.
- Все подписи интерфейса, подсказки и меню — по-русски, кроме названия приложения **Miku Focus** (явное уточнение пользователя). Английский текст озвучки не выводится строкой субтитров. Символ `୨୧` и декоративные слоганы убраны; реплики персонажа сохраняются.
- По уточнению пользователя: отдых запускается сразу после «Завершить и отдохнуть», без паузы/продолжения. auto_start управляет только следующей работой. Во время отдыха блокировать и прерывать рабочие реакции, использовать отдельные реплики и спокойный текст по умолчанию.
- Длительность работы настраивается рядом с цифрами таймера, без кнопки применения. Обычные настройки и правки категорий сохраняются автоматически. Rust принимает patch только изменяемых полей, не устаревшую копию всех настроек; до старта длительность обновляет циферблат, во время сессии применяется только к следующей и не сбрасывает timestamps/учёт. Скорость текста: 0–200 символов/с, 0 — мгновенно, по умолчанию 60; старые данные получают default без потери истории.
- На главном экране нет малого числового поля минут: только ↑/↓ справа от большого таймера. Шаг 1 минута, границы 1–480; Rust применяет относительное изменение и публикует циферблат (10:00 → 11:00). Во время работы/паузы/ожидания решения/отдыха стрелки отключены; следующую длительность можно изменить в настройках. Быстрые клики не теряются; старт и выход ждут очереди стрелок.
- Секундные снимки не должны сбрасывать ввод числовых настроек. В Svelte prop getter может переоцениваться при каждом снимке даже с тем же числом; синхронизировать черновик только при фактическом изменении сохранённого значения. Нативный smoke проверяет отсутствие малого поля и смену большого циферблата стрелками.
- В компактном режиме используется предоставленный пользователем `public/companion/SmartyMiku.png` (41×31, pixelated), основной набор эмоций не заменяется. Размер виджета меняется за правый нижний угол мышкой; Windows/X11 используют native resize, Hyprland — адресный pointer-capture адаптер только собственного окна. Размеры логические, сохраняются отдельно от позиции; default 180×190, границы 80×90–600×640. После resize запись с debounce, без фонового цикла.
- Реплики не перелистываются по времени: первый клик во время печати раскрывает строку, следующий переводит к следующей строке/реплике. Нажимается диалоговая панель или пузырь помощника; Escape/«Пропустить» остаются явным пропуском. Ожидание клика без таймера/опроса, приоритетные реакции и смена рабочего/отдых-контекста могут прерывать строку. `durationMs` старых JSON не включает автоматическое продолжение.
- Звуки: оригиналы `sfx/` не менять. Утверждены: выход → `UI SFX_InGameMenu_Close.ogg`, ↑/↓ → `high`/`low`, нажатие любой главной вкладки (включая текущую) → `menu-open`, наведение → `UI SFX_MENU_Hover.ogg`. Новые утверждённые назначения добавлять версионной миграцией, не сбрасывая прочие связи/громкости и последующие пользовательские отключения. Общий каталог TS/Rust — `src/lib/sound-catalog.json`; связи сохраняются отдельными операциями, отвязка не удаляет файлы. Hover — только включённые кнопки; Мику, диалог, resize и preview исключены; кнопки подсвечиваются. Тихий режим отключает звук, Audio загружается лениво; посимвольные blips не включены.
- Выход (кнопка/меню помощника/tray): дождаться очередей сохранения, воспроизвести выходной SFX и затемнить только собственное окно до чёрного за 1,5с, затем закрыть процесс. В тихом режиме затемнение сохраняется. Аудио выхода ограничено 3,5с, Rust fail-safe 6с — одноразовые, без фонового polling; ошибка сохранения отменяет выход. Закрытие главного окна крестиком по-прежнему переводит в помощника.
- При выходе после flush показывать «Я буду ждать нашей следующей встречи ♡» в ОБЫЧНОЙ DialoguePanel, а в помощнике — в существующем пузыре; отдельная карточка/табличка запрещена по уточнению пользователя. При выходе из настроек/дневника вернуть комнату фокуса. По последнему уточнению пользователя реплика/голос goodbye, прежний SFX и fade 1,5с запускаются ОДНОВРЕМЕННО, без предварительного ожидания прощания. Реплика остаётся в DOM минимум 1,5с и затухает вместе с окном; голос до естественного конца с общим лимитом загрузки/голоса 2,2с. Закрыть процесс только после всех трёх веток. Без клика/обычного диалогового контроллера; quiet/hide/stop освобождают голос и поздний Blob. В quiet остаются текст и fade, controls заблокированы, реплика доступна AT-SPI. Максимальный frontend budget после flush 3,5с, Rust fail-safe 6с. Новая строка goodbye/app_quit добавляется к исходным 20 строкам только при отсутствии события, в памяти, без перезаписи пользовательского JSON/его прощания; семь согласованных en не менять.
- Вопрос `focus_complete` («Ещё пять минут или отдых?»), его текст и голос — только в видимом большом окне, не в помощнике. Компактное окно по-прежнему может claim событие ради единственного SFX завершения, но ReactionController запрещает вопрос и его fallback. При открытии главного окна ожидание решения восстанавливает Happy/вопрос из Rust AwaitingDecision без повторного completion SFX; таймер/историю не менять. Скрытый/minimized WebView не создаёт/не держит диалоговый контроллер; при появлении главного окна вопрос восстанавливается. Остальные реплики помощника сохраняются.
- Обращение Senpai/сэмпай во встроенных 20 строках оставлено только в welcome, focus_complete, extra_surprised, return, record и goal. Остальные строки и обычный fallback без постоянного обращения; ID/порядок/эмоции/voice bindings не менять. Пользовательский JSON диалогов и записанные аудиофайлы не перезаписывать.
- Последующее точное уточнение английских текстов: en в welcome/start/extension/finish/break-skipped/goal/touch заменены на предоставленные пользователем строки; en finish дополнительно содержит Senpai. Русские ru (включая прежние шесть обращений), эмоции, события, идентификаторы и все остальные параметры остаются без изменений.
- Предоставленная пользователем озвучка из `Downloads/Telegram Desktop/v2.rar` сопоставлена по названиям и импортирована в Linux через штатный import_asset: 21 voice ID, включая goodbye. Оригиналы/старые assets не менять, громкости/SFX/историю не сбрасывать. Это локальные пользовательские привязки, не встроенная библиотека/не экспорт Obsidian. Соответствие и ограничения: `docs/VOICE_RECORDINGS.md`.
- Локальный WAV/OGG голоса и voice preview загружаются только для текущей строки в временный Blob с явным audio/wav/audio/ogg: прямой asset:// media в WebKit давал FormatError/тишину. Не кэшировать/не предзагружать библиотеку голосов; предел 20 МиБ, fetch отменяется при stop/hide/quiet, URL освобождается на конце/прерывании и после поздней загрузки. CSP разрешает fetch только локального asset:/http://asset.localhost, область файлов по-прежнему $APPDATA/assets/**, внешние источники не разрешать.
- high/low применяются ко всем направленным стрелкам: числовые настройки (native spinner и ↑/↓), календарь (вперёд/назад), стрелочные клавиши ползунков и resize-захвата помощника. Использовать существующие duration_up/down и общую громкость/тихий режим, не сбрасывать пользовательские назначения. Ввод/вставка текста, drag ползунка, снимки состояния и неизменившееся число не создают звука; числовая настройка звучит после успешного сохранения.
- Hover перезапускается сразу на каждом новом входе на кнопку, без cooldown/ожидания окончания предыдущего; отдельный ленивый hover-канал не обрывает нажатия/таймер. Не создавать неограниченное наложение голосов: максимум один текущий hover и один основной SFX; stop/quiet/hide освобождают оба, включая поздние загрузки. Внутренние вкладки настроек/дневника/звуков (также повторный клик и раскрытие разделов звука) → choice-hover через menu_choice; три главные вкладки сохраняют menu-open. Миграция soundDefaultsVersion 1→2 добавляет только menu_choice, не включает заново ранее отключённые события.
- Выбор категории в комнате фокуса — доступное меню кнопок (не native select, у его popup нет DOM hover). Наведение на кнопку/категорию → существующий choice_hover, нажатие → menu_choice/choice-hover.wav; пользовательские назначения и тихий режим сохраняются. Клавиатура: ↑/↓, Home/End, Enter/Space, Escape, уход фокуса/клик снаружи. Смена категории не изменяет уже начатую сессию.
- «↺ Сбросить сессии» обнуляет только Rust timer.cycle: 2/4 → 1/4. Текущая работа/пауза/ожидание/отдых, дедлайн и история сохраняются; новый длинный отдых — после нового полного цикла. Обычный «↺ Сбросить» не меняется. Сброс цикла не генерирует рабочую реплику.
- Встроенные SFX используют два ленивых переиспользуемых HTMLAudioElement — main/hover — и кэш Blob URL максимум девяти утверждённых файлов. Не создавать новый Audio на каждое наведение/клик: это воспроизводимо вешало WebKit. Повтор того же файла — currentTime=0/play без смены src/load. При естественном onended не выгружать/не pause/load: короткий PCM ещё может находиться в очереди вывода. Quiet/hide/stop освобождают оба элемента и кэш; устаревшие загрузки освобождают URL и не играют. Пользовательские длинные файлы/preview/голос не загружать в этот кэш.
- Web Audio путь 0.1.9 удалён после реального PCM-сравнения: suspend обрезал high/low, а громкость отличалась от HTML preview; drain/предбуфер не устранили все потери атаки. Не возвращать этот путь или произвольные задержки без проверки PCM. Переиспользование media-элементов сохраняет немедленный hover без ожидания предыдущего, максимум один hover и один основной сигнал.
- По уточнению пользователя, верх основного спрайта касается верхнего края панели комнаты фокуса. Масштаб по полной высоте панели с сохранением пропорций и центрированием в области Мику; без прежнего сдвига вниз на 8px. Горизонтальное переполнение обрезается только областью персонажа, не залезает на таймер. Original PNG и пиксельный помощник не меняются; оба слоя смены эмоции выравниваются одинаково.
- Obsidian: только односторонняя автовыгрузка аналитического JSON в выбранное пользователем существующее хранилище, `Miku Focus/Данные/{linux,windows}.json`. Локальные история/таймеры ОС независимы, автоматического импорта/слияния/плагина Obsidian нет. Полные рабочие сегменты, отдых и категории без путей ресурсов/копии настроек; текущая сессия в sessions ровно один раз, сегменты ограничены capturedAt/deadline. Идентификатор источника и папка — отдельный локальный obsidian.json + backup, повреждённый конфиг не затирать. Не трогать заметки/.obsidian (выбор .obsidian/её подкаталогов запрещён); unknown/corrupt/other-source JSON и symlink output/subdirs/lock не перезаписывать. Папки создавать только при явном подключении, не восстанавливать пустую точку монтирования автоматически. Дисковая работа — отдельный worker без Rust runtime mutex, одна latest-pending задача, неизменившиеся idle-данные не писать. Retry на существующем 30с пробуждении, без нового polling; финальное ожидание до 2с и ошибка внешнего диска не отменяет локально сохранённый выход. Native chooser: Linux — существующий GTK на UI thread (не второй GTK thread rfd), Windows — Rust tauri-plugin-dialog; frontend не получает generic fs/dialog permissions. Отключение не удаляет файлы, пользовательские правки валидного generated JSON могут заменяться (явно указано в UI).

В FocusMikuAll вручную установлена Dataview-панель из `integrations/obsidian`, в Arch/Win — две новые заметки, всего шесть новых файлов без перезаписи заметок/.obsidian. Это не автоматическая установка плагинов/заметок приложением. Windows JSON пока отсутствует; путь FocusMikuWin надо отдельно выбрать в Windows. Панель read-only/offline, слушает только два файла, без собственного polling; cleanup и замена подписок при повторном render Dataview обязательны. Данные источников/категории не сливать автоматически; отсутствующий Windows не подменять нулевой/примерной историей.
- GitHub Releases: `.github/workflows/release.yml` — только version-tag push или workflow_dispatch, не обычные коммиты/PR/расписание. Standard Windows/Ubuntu runner, Arch-сборка внутри одноразового Arch-контейнера (его pacman -Syu не разрешает обновлять локальную систему). В private repo runner заблокирован без явного allow_private_build либо ENABLE_PRIVATE_BUILDS=true; платёжные настройки/видимость repo не менять без запроса. Manual → artifacts (3 дня), tag → только draft после обеих платформ; публичный release остаётся ручным решением. Только final job contents:write, actions SHA-pinned, allowlist двух пакетов + SHA256SUMS/BUILD_INFO, никакой истории/голосов/app-data. Версии npm/locks/Cargo/Tauri/PKGBUILD и тег должны совпадать. Windows NSIS по-русски/currentUser, неподписанный; UI/установку Windows не считать проверенными по локальным mock-тестам. Инструкция: docs/RELEASING.md.

Разрешена публикация скачиваемой **беты**, не stable: тег v0.1.13-beta.1, prerelease=true, latest=false; нативная core-версия пока 0.1.13. ## Проверки
Система тем пользователя: только по отдельному явному разрешению допустима ручная установка в её источники. Сейчас общий `~/.config/waybar/miku-focus.jsonc` включён в `_base/modern/aurora/tty/waybar.jsonc` с отдельным добавлением имени модуля в массив каждого источника; общий `miku-focus.css` импортирован всеми пятью темами. Не ограничиваться активными config/CSS, которые apply-theme перезаписывает. Сохранять JSONC-комментарии/остальные модули; бинды/VPN/прочие компоненты и theme scripts не менять. Для проверок использовать `scripts/check-waybar-themes.py`: private app-data/bus/PID и sandbox HOME для apply/startup, не общий pkill/switch-theme и не logout пользователя. Это не автоматическая функция приложения по правке конфигов.
Панель: backgroundMode по умолчанию Companion; Panel скрывает оба окна, Rust остаётся единственным таймером. Waybar — постоянный --waybar CLI без GUI/дискового polling, тот же профиль app-data; --show-main только открывает существующее окно. Не менять/не перезапускать пользовательский Waybar/Hyprland. В UI выдавать готовый JSON; OS config правится пользователем. IPC abstract Linux socket same-UID/SO_PEERCRED, bounded latest-wins; в полностью скрытом режиме нет UI-clock/реплик/SFX, вопрос и completion event ждут main. Windows — native числовой tray/tooltip/menu, без Explorer extensions; bitmap/компиляцию API на Linux не выдавать за Windows проверку. Native Waybar smoke — только собственный PID/отдельный конфиг/private D-Bus, exclusive=false; cleanup только своего process group и bus PID, не пользовательской панели.
`npm run check`, `npm test`, `cargo test --manifest-path src-tauri/Cargo.toml`, `npm run tauri build -- --no-bundle`.
Не запускать несколько Cargo сборок одновременно: RAM всего 7,1 ГиБ, сборка jobs=1, debug symbols отключены.
Native chooser smoke: GSETTINGS_BACKEND=memory в обоих runner, чтобы не записывать предпочтения тестового диалога в пользовательский dconf. В Xvfb xdotool search — с --all (PID и имя одновременно), диалог вписывать в private экран без WM; путь вводить без завершающего /, подтверждать один раз, при reconnect проверять именно выбранный корень, не generated child.
Нативные тесты запускают собственный процесс с отдельным XDG_DATA_HOME и выбирают его только по полученному PID, не через «последний miku-focus»/общий класс окна. Пользовательский экземпляр не закрывать и его историю не менять. Для длительного сценария без ввода пользователя использовать private Xvfb + private D-Bus (`scripts/run-headless-smoke.py`); результат X11 не выдавать за Wayland. Два Xvfb smoke не запускать одновременно: в текущей среде параллельные launcher конфликтовали по экрану/вводу.
Проверка SFX при нулевой громкости не доказывает корректный аудиовыход. `scripts/check-audio-output.py` запускает собственный Wayland PID с отдельными данными/volume=0.5 и временным null sink, записывает только его monitor, проверяет ненулевой PCM/стабильную энергию high после idle/quiet/смены окна и тишину quiet. Не записывать микрофон, default monitor или чужие приложения; не менять default sink/системную громкость, выгружать только созданный тестом module ID. Все native runner задают тестовые PULSE_PROP application.name/module-stream-restore.id, чтобы тестовые уровни/маршруты не смешивались с приложением пользователя. Использовать raw parec и дождаться конкретного recorder PID и первых PCM-байтов до нажатия; FFmpeg probing/timestamps могли терять изолированные 60мс сигналы и давать ложную тишину.
