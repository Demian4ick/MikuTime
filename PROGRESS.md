## 0.1.6: утверждённые SFX, чёрное затухание и возврат победного диалога (2026-11-17)
- Применены пять назначений пользователя: выход → длинный Close OGG, стрелки ↑/↓ → high/low, все главные вкладки (включая повторный клик) → menu-open, hover кнопок → новый `UI SFX_MENU_Hover.ogg`. Одноразовая миграция применяет именно эти пять связей, сохраняет остальные поля/связи и не отменяет последующие отключения.
- Hover ограничен включёнными кнопками; поля, ссылки, Мику, диалоговая панель/пузырь, resize и preview исключены. Обычные кнопки получили явную светлую подсветку/обводку без постоянной анимации.
- Все штатные пути выхода, включая tray, проходят Rust-запрос → сохранение → локальный SFX/чёрная CSS-завеса → финальный checkpoint/exit. Затемнение 1,5с; здоровый Close 2,523с не обрезается. - Причина пропавшей победы: compact уже claimed `focus_complete`, новый главный ReactionController не имел события и возвращался к Neutral. Теперь AwaitingDecision из Rust восстанавливает Happy/вопрос из актуального каталога диалогов, открывает комнату фокуса и не повторяет SFX/начисление времени. Победный fallback остаётся до решения.

## Решения
- Локальное JSON-хранилище вместо SQLite: не требует дополнительного плагина/БД.
- Восстановление работы на паузе с последнего checkpoint; с 0.1.1 отдых продолжается автоматически (не считать время отсутствия приложения).
- Linux-поставка: нативный binary + Arch PKGBUILD; AppImage не обязателен и не требует linuxdeploy/FUSE для первой сборки.
